# 서버 연동 RPG 프로토타입
> Unity 클라이언트와 ASP.NET Core 서버, MySQL을 연결해 만든 2D RPG 프로토타입입니다.

로그인부터 몬스터 사냥, 골드 저장까지의 흐름을 구현했습니다.

🎬 [시연 영상 보기 (Google Drive)](https://drive.google.com/file/d/1wuD2brEH9sN4zHWu7UTov1lw8DLVQKZG/view)

## 1. 기술 스택
- **Client**: Unity 2022.3 (C#)
- **Server**: ASP.NET Core Web API (.NET 8)
- **Database**: MySQL (Entity Framework Core, Pomelo)
- **통신**: HTTP + JSON (REST API)
- **라이브러리**: BCrypt.Net (비밀번호 해시), Swagger (API 테스트)

## 2. 폴더 구조
- `/Client_RPG`: Unity 프로젝트
- `/Server_RPG`: ASP.NET Core 서버 프로젝트
- `/docs`: 문서

## 3. 구현 기능

### 로그인
- 이메일과 비밀번호로 로그인합니다. 서버는 DB에 저장된 BCrypt 해시와 비밀번호를 비교합니다.
- 로그인에 성공하면 캐릭터 정보(닉네임, 레벨, 골드, 체력, 공격력, 마지막 위치)를 받아 게임 씬으로 넘어갑니다.

### 캐릭터 이동과 위치 저장
- 키보드(방향키·WASD) 이동과 마우스 클릭 이동을 지원합니다.
- 클라이언트가 5초마다 캐릭터 위치를 서버로 보내 DB에 저장합니다. 다시 접속하면 마지막으로 저장된 위치에서 시작합니다.

### 몬스터 스폰과 리젠
- 서버가 시작될 때 DB의 스포너 정보(위치, 범위, 최대 마릿수)를 읽어 몬스터를 서버 메모리에 생성합니다.
- 몬스터가 죽으면 리젠 시간을 큐에 넣고, `BackgroundService`가 1초마다 확인해서 시간이 된 몬스터를 다시 생성합니다.
- 클라이언트는 2초마다 서버에서 몬스터 목록을 받아, 새로 생긴 몬스터는 화면에 만들고 목록에서 사라진 몬스터는 지웁니다.

### 전투
- 몬스터를 클릭하면 공격 사거리까지 따라간 뒤 공격하고, 서버에 공격 요청을 보냅니다.
- 서버는 공격을 처리하기 전에 아래 세 가지를 확인합니다.
  - 마지막으로 저장된 위치에서 이동할 수 있는 거리보다 많이 움직이지 않았는지
  - 몬스터가 스폰 범위를 벗어나지 않았는지
  - 플레이어와 몬스터 사이 거리가 공격 사거리 안인지
- 확인을 통과하면 서버 메모리에 있는 몬스터 체력을 깎고, 몬스터가 죽으면 골드(현재 100 고정)를 DB에 저장합니다.

## 4. 데이터 저장 위치
| 데이터 | 저장 위치 |
|---|---|
| 계정, 캐릭터(골드, 위치, 능력치) | MySQL |
| 몬스터 정보, 스포너 설정 | MySQL |
| 살아 있는 몬스터(체력, 위치), 리젠 대기 목록 | 서버 메모리 |

## 5. API 목록
| Method | Endpoint | 설명 |
|---|---|---|
| POST | `/api/Auth/login` | 로그인, 캐릭터 정보 반환 |
| POST | `/api/Player/sync-position` | 캐릭터 위치 저장 |
| POST | `/api/Player/attack` | 공격 확인 및 처리 |
| GET | `/api/Monster` | 몬스터 정보 전체 조회 |
| GET | `/api/Monster/{id}` | 몬스터 정보 단건 조회 |
| GET | `/api/Monster/live-list?mapId={id}` | 맵에 살아 있는 몬스터 목록 조회 |
