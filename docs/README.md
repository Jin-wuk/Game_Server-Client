# 서버 연동 RPG 프로토타입
> **클라이언트의 요청을 서버가 검증하는 서버 권위 구조의 2D RPG 프로토타입**

Unity 클라이언트와 ASP.NET Core 서버, MySQL을 직접 연결해 로그인부터 몬스터 사냥까지의 흐름을 구현했습니다.

## 1. 기술 스택
- **Client**: Unity 2022.3 LTS (C#)
- **Server**: ASP.NET Core Web API (.NET 8)
- **Database**: MySQL (Entity Framework Core, Pomelo)
- **Communication**: JSON over HTTP (REST API)
- **Library**: BCrypt.Net (비밀번호 해시), Swagger (API 테스트)

## 2. 폴더 구조 (Monorepo)
- `/Client_RPG`: Unity 프로젝트 (입력, 이동, 전투 연출, UI)
- `/Server_RPG`: ASP.NET Core 프로젝트 (요청 검증, 몬스터 관리, DB 저장)
- `/docs`: 아키텍처, DB 명세 문서

## 3. 구현 기능

### 로그인
- 이메일과 비밀번호로 로그인하며, 서버는 BCrypt 해시로 비밀번호를 검증합니다.
- 로그인에 성공하면 계정에 연결된 캐릭터 정보(닉네임, 레벨, 골드, 체력, 공격력, 마지막 위치)를 받아 게임을 시작합니다.

### 캐릭터 이동과 위치 저장
- 키보드(방향키·WASD) 이동과 마우스 클릭 이동을 지원합니다.
- 클라이언트가 5초마다 캐릭터 위치를 서버에 보내 DB에 저장하고, 다시 접속하면 마지막 위치에서 시작합니다.

### 몬스터 스폰과 리젠
- 서버가 시작될 때 DB의 스포너 정보(위치, 범위, 최대 수)를 읽어 몬스터 인스턴스를 서버 메모리에 생성합니다.
- 몬스터가 죽으면 리젠 예약을 큐에 넣고, 백그라운드 서비스가 1초마다 확인해 시간이 되면 다시 생성합니다.
- 클라이언트는 2초마다 살아 있는 몬스터 목록을 받아 새로 생긴 몬스터는 생성하고 사라진 몬스터는 제거합니다.

### 전투와 서버 검증
- 몬스터를 클릭하면 사거리 안까지 추적한 뒤 공격하고, 공격 요청을 서버에 보냅니다.
- 서버는 요청을 처리하기 전에 다음 항목을 검증합니다.
  - **이동 거리**: 마지막으로 저장된 위치에서 이동 가능한 거리를 넘었는지
  - **몬스터 위치**: 몬스터가 스폰 범위를 벗어났는지
  - **사거리**: 플레이어와 몬스터 사이 거리가 공격 사거리 안인지
- 검증을 통과하면 서버 메모리의 몬스터 체력을 깎고, 처치하면 골드 보상을 DB에 저장합니다.

## 4. 데이터 관리 방식
| 데이터 | 저장 위치 | 이유 |
|---|---|---|
| 계정, 캐릭터(골드, 위치, 능력치) | MySQL | 접속이 끊겨도 유지되어야 하는 영구 데이터 |
| 몬스터 도감, 스포너 설정 | MySQL | 기획 데이터 |
| 살아 있는 몬스터 인스턴스, 리젠 예약 | 서버 메모리 | 자주 바뀌고 서버 재시작 시 다시 만들어도 되는 데이터 |

## 5. API 목록
| Method | Endpoint | 설명 |
|---|---|---|
| POST | `/api/Auth/login` | 로그인, 캐릭터 정보 반환 |
| POST | `/api/Player/sync-position` | 캐릭터 위치 저장 |
| POST | `/api/Player/attack` | 공격 검증 및 처리 |
| GET | `/api/Monster` | 몬스터 도감 전체 조회 |
| GET | `/api/Monster/{id}` | 몬스터 도감 단건 조회 |
| GET | `/api/Monster/live-list?mapId={id}` | 맵의 살아 있는 몬스터 목록 조회 |
